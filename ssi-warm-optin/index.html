How to read this wireframe

A wireframe locks structure, not words. Every content slot below is a labelled box carrying three things, so the page doubles as the copy brief. Full table at the bottom.

  • SLOT TYPE what goes in the box: H1, subhead, body, bullet, CTA, stat, image, video. Set in mono, top left of every box.
  • WORD BUDGET the pill on the top right of every box is a word budget: the length the layout is built for. Writing outside it breaks the fold.
  • JOB the one thing that slot has to accomplish. Write to the job, not to the box.
  • SPEC the grey rail under each section header: layout, fold budget, media, element counts, reference.
  • SWAP CONSTANT CUSTOMIZE V2 variant behaviour. SWAP changes per page variant, CONSTANT is written once and reused, CUSTOMIZE V2 is constant now and hand-tuned per asset later.
  • DECIDED the four structural questions this wireframe raised are settled. Each is recorded in place, with the reasoning, so it does not get re-litigated.

Keep the fit block. It is in the client-agnostic standard and on the live page, but was absent from the v1 structure map. Rules that apply to every slot

  • One CTA label family. The same words at header, mid-page CTA, final CTA and sticky mobile bar. No secondary button anywhere.
  • Cleared proof only. Any name, quote or number that is not cleared stays out. It is never replaced with a plausible substitute.
  • No em dashes. House rule, applies to every line on the page.
  • Budgets are structural. They come from the fold budgets in each section spec. Overrunning a budget moves the first fold, which is the one thing this wireframe exists to protect.
  • The four structural questions are settled. Decisions A to D are recorded in place on the page above, with the reasoning. Nothing is blocking copy except the client disclaimer.
